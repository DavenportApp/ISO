# 7.5 Documented Information

## Requirement

### 7.5.1 General

The organization's QMS shall include:
- Documented information required by ISO 9001:2026
- Documented information determined by the organization as necessary for QMS effectiveness
- The extent of documented information can differ based on organization size, activities complexity, process complexity, and personnel competence

### 7.5.2 Creating and Updating

When creating and updating documented information, ensure appropriate:
- Identification and description (title, date, author, reference number)
- Format (language, software version, graphics) and media (paper, electronic)
- Review and approval for suitability and adequacy

### 7.5.3 Control of Documented Information

Documented information shall be controlled to ensure:
- It is available and suitable for use, where and when needed
- It is adequately protected (from loss of confidentiality, improper use, or loss of integrity)

Control activities shall address:
- Distribution, access, retrieval, and use
- Storage and preservation (including preservation of legibility)
- Control of changes (version control)
- Retention and disposition
- Prevention of unintended use of obsolete documents

## Understanding Documented Information

### What is Documented Information?

**ISO 9001:2026 uses "documented information" to cover:**
- **Documents** (previously "documented procedures"): Information that needs to be controlled and maintained
- **Records** (previously "quality records"): Evidence of conformity and effectiveness

### Documented vs. Document vs. Record

| Term | Definition | Examples | Control Need |
|------|------------|----------|--------------|
| Information | Knowledge or data | Any quality-related info | May or may not need control |
| Documented Information | Information required to be controlled | Procedures, records, plans | Must be controlled |
| Document | Information requiring control and maintenance | Procedures, work instructions | High - prevent obsolete use |
| Record | Evidence of results achieved | Test results, audit reports | Medium - ensure availability |

### Required vs. Determined Documented Information

**Required by ISO 9001:2026:**
- Scope of QMS (4.3)
- Quality policy (5.2)
- Quality objectives (6.2)
- Operational planning and control info (8.1)
- Evidence of fitness for purpose of monitoring/measuring resources (7.1.5)
- Competence evidence (7.2)
- And others as specified throughout the standard

**Determined by Organization:**
- Process descriptions and flowcharts
- Work instructions and job aids
- Forms and templates
- Risk assessments
- Knowledge repositories
- Dashboards and reports
- Digital documentation (ISO 9001:2026)

## Document Control System

### Document Lifecycle

```
Create → Review → Approve → Distribute → Use → Update → Archive/Obsolete
   ↑                                                            ↓
   └────────────────────── Continuous Improvement ─────────────┘
```

### Document Types and Categories

**Level 1: Quality Manual (Optional)**
- High-level QMS description
- Scope and exclusions
- Process interactions
- Reference to procedures

**Level 2: Procedures**
- Documented procedures as required
- Process descriptions
- Cross-functional processes
- Management system procedures

**Level 3: Work Instructions**
- Detailed task instructions
- Standard operating procedures
- Job aids and checklists
- Technical specifications

**Level 4: Forms and Templates**
- Data collection forms
- Report templates
- Checklists
- Standard formats

**Supporting Documents:**
- External documents (standards, regulations, customer specs)
- Records and evidence
- Reference materials
- Guidelines and best practices

### Document Identification

**Essential Elements:**
- **Unique Identifier:** Document number or code
- **Title:** Clear, descriptive name
- **Revision/Version:** Track changes over time
- **Date:** Issue date, revision date
- **Author/Owner:** Who created/maintains it
- **Approval:** Who authorized it
- **Status:** Draft, approved, obsolete

**Example Document ID Structure:**
- **QP-8.1-001-R3** 
  - QP = Quality Procedure
  - 8.1 = ISO clause reference
  - 001 = Sequential number
  - R3 = Revision 3

**Metadata (Digital Documents - ISO 9001:2026):**
- Keywords and tags
- Category and classification
- Access permissions
- Related documents
- Change history
- Search optimization

### Document Creation Process

**Step 1: Initiate**
- Identify need for documentation
- Assign document owner
- Define scope and purpose
- Determine format and template

**Step 2: Draft**
- Research and gather information
- Write content clearly and concisely
- Include necessary details
- Use standard template
- Add visuals if helpful (flowcharts, diagrams)

**Step 3: Review**
- Technical review by subject matter experts
- Quality review for format and compliance
- Usability review by end users
- Legal/regulatory review if applicable
- Stakeholder review and input

**Step 4: Approve**
- Submit for formal approval
- Approval by authorized person(s)
- Document approval signatures/electronic approval
- Finalize document status

**Step 5: Release and Distribute**
- Assign final document number and version
- Publish to document management system
- Notify relevant personnel
- Make available at point of use
- Remove obsolete versions
- Provide training if needed

### Document Review and Update

**Periodic Review:**
- Scheduled reviews (e.g., annually, every 2-3 years)
- Review for accuracy and relevance
- Update for changes in process or requirements
- Check for alignment with current practice
- Consider user feedback
- Verify regulatory compliance

**Change-Driven Review:**
- Process changes
- Regulatory updates
- Technology changes
- Organizational changes
- Audit findings
- Non-conformities or improvements
- Customer requirements

**Review Process:**
1. Review triggered by schedule or change
2. Document owner reviews and updates draft
3. Changes highlighted or tracked
4. Re-review by stakeholders
5. Re-approval by authorized person
6. New version issued
7. Previous version archived
8. Users notified of changes

**Version Control:**
- Increment version/revision number
- Document change summary
- Maintain change history log
- Distinguish between minor edits and major revisions
  - Minor (e.g., 1.1, 1.2): Typos, clarifications, formatting
  - Major (e.g., 2.0, 3.0): Significant content or process changes

## Record Control System

### Record Types

**Quality Records:**
- Inspection and test records
- Calibration certificates
- Non-conformity reports
- Corrective action records
- Audit reports
- Management review minutes
- Training records
- Customer complaints and feedback

**Operational Records:**
- Production logs and batch records
- Process monitoring data
- Material traceability records
- Supplier documentation
- Maintenance records
- Environmental monitoring

**Digital Records (ISO 9001:2026):**
- System-generated logs
- Digital signatures and timestamps
- Automated test data
- IoT sensor data
- Video and photographic evidence
- Email and electronic communications
- Cloud-based records
- Blockchain traceability records

### Record Requirements

**Legibility:**
- Clearly readable
- Good quality reproduction
- Proper contrast (for paper)
- Adequate resolution (for digital)
- Viewable formats preserved

**Identification:**
- Record type clearly identified
- Date and time stamps
- Product/service identification
- Personnel identification (who performed/recorded)
- Equipment or process identification

**Traceability:**
- Link to related records
- Product/batch traceability
- Process traceability
- Temporal traceability (timeline)

**Integrity:**
- Protection from alteration
- Audit trails for changes (digital)
- Authentication (signatures, electronic signatures)
- Tamper-evident or tamper-proof
- Backup and disaster recovery

### Record Retention

**Retention Period Determination:**
- Regulatory requirements
- Customer requirements
- Product lifecycle and warranty
- Legal and liability considerations
- Business needs and value
- Storage capacity and costs

**Retention Schedule Example:**

| Record Type | Retention Period | Storage Location | Disposition Method |
|-------------|------------------|------------------|-------------------|
| Quality records | 5 years | Electronic archive | Secure deletion |
| Audit reports | 10 years | Document management system | Archive to offline storage |
| Training records | Duration of employment + 3 years | HR system | Secure deletion |
| Calibration certificates | Life of equipment + 2 years | Quality database | Secure deletion |
| Customer complaints | 7 years | CRM system | Secure deletion |
| Environmental monitoring | 10 years | Environmental database | Archive |
| [Record type] | [Period] | [Location] | [Method] |

**Disposition:**
- Review at end of retention period
- Determine if extension needed
- Secure deletion or destruction
- Certificate of destruction if required
- Update records inventory

### Electronic Signatures and Authentication

**Types of Electronic Signatures:**
- **Simple:** Click to accept, typed name
- **Advanced:** Cryptographically linked to signer, tamper-evident
- **Qualified:** Meets highest regulatory standards (e.g., EU eIDAS)

**Requirements for Electronic Signatures (21 CFR Part 11 principles):**
- Unique to individual
- Verified upon use
- Under sole control of signer
- Linked to record so alteration is evident
- Includes date and time stamp
- Meaning of signature clear (e.g., reviewed, approved)

**Implementation:**
- E-signature software (DocuSign, Adobe Sign)
- QMS with built-in e-signature
- Digital certificates and PKI
- Biometric authentication
- Two-factor authentication

## Document Control Procedures

### Procedure: Creating New Document

1. **Initiate Request**
   - Complete document request form
   - Justify need for new document
   - Assign document owner

2. **Draft Document**
   - Use standard template
   - Write clear, concise content
   - Include all required elements
   - Save as draft in DMS

3. **Review**
   - Circulate for stakeholder review
   - Collect and incorporate feedback
   - Technical and quality review

4. **Approve**
   - Submit for formal approval
   - Obtain required signatures/approvals
   - Update approval metadata

5. **Publish**
   - Assign final document number
   - Change status to "Approved"
   - Make available in DMS
   - Notify users
   - Provide training if needed

### Procedure: Revising Existing Document

1. **Identify Need for Change**
   - Scheduled review, or
   - Change request initiated

2. **Draft Revision**
   - Check out document from DMS
   - Make necessary changes
   - Track changes or highlight edits
   - Document reason for change

3. **Review Changes**
   - Review by stakeholders
   - Focus on changed sections
   - Verify change adequacy

4. **Approve Revision**
   - Obtain approval for revised version
   - Increment version number
   - Update change history

5. **Publish Revised Version**
   - Replace current version with new version
   - Archive previous version
   - Notify users of changes
   - Provide training on significant changes

### Procedure: Removing Obsolete Documents

1. **Identify Obsolete**
   - Document superseded by new version
   - Process no longer used
   - Product discontinued
   - Regulatory change

2. **Archive or Remove**
   - Change status to "Obsolete"
   - Remove from active document lists
   - Move to archive or restricted folder
   - Prevent access by general users
   - Maintain for retention period if needed

3. **Retrieve Physical Copies**
   - Identify locations of physical copies
   - Collect and destroy or stamp "OBSOLETE"
   - Verify removal from points of use

4. **Communicate**
   - Notify users of obsolete document
   - Direct to current version
   - Update training materials

### Procedure: Managing External Documents

1. **Identify External Documents**
   - Standards (ISO, ASTM, etc.)
   - Regulations and legal requirements
   - Customer specifications
   - Supplier documents
   - Technical references

2. **Obtain and Register**
   - Acquire authorized copies
   - Register in external document list
   - Assign internal tracking number
   - Note version/date

3. **Control Distribution**
   - Determine who needs access
   - Distribute controlled copies
   - Restrict copying if required
   - Track distribution

4. **Monitor for Updates**
   - Monitor for new revisions or editions
   - Subscribe to update services
   - Check periodically with source
   - Review relevance periodically

5. **Update and Replace**
   - Obtain updated version
   - Replace obsolete version
   - Notify users of changes
   - Assess impact on processes

## Master Lists and Registers

### Master Document List

**Content:**
- Document number/ID
- Document title
- Revision/version
- Date
- Owner/Author
- Approval authority
- Location/Link
- Status (draft, approved, obsolete)
- Distribution list

**Maintenance:**
- Update whenever document is added, revised, or obsoleted
- Maintain in accessible location (e.g., DMS, quality portal)
- Ensure accuracy and currentness
- Regular audit and verification

### External Document Register

**Content:**
- External document title
- Source/Publisher
- Edition/Version/Date
- Internal reference number
- Relevant to (processes, products)
- Owner/Custodian
- Location
- Review frequency
- Next review date

### Record Register/Retention Schedule

**Content:**
- Record type
- Purpose
- Retention period
- Storage location (physical/digital)
- Access permissions
- Disposition method
- Regulatory/customer basis
- Record owner

## Best Practices

### Document Control Excellence

**1. Keep it Simple:**
- Only document what's necessary
- Avoid over-documentation
- Use simple language and format
- Visual aids (flowcharts, diagrams)
- Layered approach (high-level to detailed)

**2. Make it Accessible:**
- Easy to find and retrieve
- Available at point of use
- Mobile access for field workers
- Search-friendly
- Multi-language if needed

**3. Engage Document Users:**
- Involve users in document creation
- User testing before finalizing
- Gather continuous feedback
- Make it practical and usable
- Provide context and examples

**4. Leverage Technology:**
- Digital document management system
- Automated workflows
- Electronic signatures
- Cloud-based for accessibility
- Integration with other systems
- AI for search and recommendations (ISO 9001:2026)

**5. Maintain Quality:**
- Regular reviews and updates
- Clear ownership and accountability
- Quality checks before approval
- Consistency in format and style
- Continuous improvement

**6. Ensure Security:**
- Access controls
- Backup and recovery
- Cybersecurity measures
- Confidentiality protection
- Audit trails

**7. Go Green (ISO 9001:2026):**
- Minimize paper use
- Digital-first approach
- Efficient storage
- Reduce printing
- Sustainable practices

## Common Challenges and Solutions

| Challenge | Solution |
|-----------|----------|
| Document overload | Simplify, consolidate, retire unnecessary documents |
| Outdated documents | Regular review schedule, change-triggered reviews, document ownership |
| Poor user adoption | User-friendly system, training, make it valuable, demonstrate benefits |
| Version confusion | Strong version control, clear labeling, automatic obsolete removal |
| Difficult to find | Good search, logical organization, metadata, links between related docs |
| Resistance to digital | Training, support, show value, phased approach, champion users |
| Security concerns | Access controls, encryption, cybersecurity, backup, incident response |
| Compliance gaps | Retention schedule, audit trails, regular compliance audits, policy enforcement |
